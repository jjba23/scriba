** Ways to install
:PROPERTIES:
:CUSTOM_ID: ways-to-install
:END:

/Four routes to the same 0.5.2, from the most automated to the most manual.  They all build the tag this documentation covers./

*** From the Guix channel
:PROPERTIES:
:CUSTOM_ID: from-the-guix-channel
:END:
*GNU Guix* is the functional package manager this project is developed with: a build is a pure function of its inputs, so the same recipe gives the same result everywhere, and an upgrade that goes wrong can be rolled back.

The jointhefreeworld channel carries ~guile-scriba~ at 0.5.2, so a checkout of the channel is enough — no package definition to write:

#+begin_src shell
git clone https://codeberg.org/jjba23/guix-jointhefreeworld.git
guix install -L ./guix-jointhefreeworld guile-scriba
#+end_src

Add the channel to ~$HOME/.config/guix/channels.scm~ (the channel's README has the four lines) and a plain ~guix install guile-scriba~ keeps working on every later ~guix pull~.

*** From the Nix flake
:PROPERTIES:
:CUSTOM_ID: from-the-nix-flake
:END:
*Nix* offers the same declarative, reproducible model with its own language, its own store and a binary cache, and it is a natural fit if the rest of your machine is already described in Nix.

The jointhefreeworld flake builds this project with this repository's own expression, so the package cannot drift from the source:

#+begin_src shell
nix build github:jjba23/nix-jointhefreeworld#guile-scriba
#+end_src

The same attribute is available as an overlay, so ~pkgs.jointhefreeworld.guile-scriba~ works inside a NixOS or home-manager configuration too.

*** As a container image
:PROPERTIES:
:CUSTOM_ID: as-a-container-image
:END:
*Podman or Docker* is the route that puts nothing on the host: the ~Dockerfile~ in this repository builds the project in a builder stage and copies only what it installed into a runtime stage, so the image is small and the host keeps its own toolchain untouched.

#+begin_src shell
podman build -t scriba .   # docker build -t scriba . also works
podman run --rm -it scriba
#+end_src

The image's entry point is Guile, with scriba on its load path, which makes it useful for a quick try and for reproducing a bug on a clean system.

*** As a distribution package
:PROPERTIES:
:CUSTOM_ID: as-a-distribution-package
:END:
*Debian, openSUSE and Arch* each get the project through their own package manager.  Packaging lives in this repository under ~packaging/~ and is pinned to the same release tag, so the recipes and the sources they build are versioned together.

None of the three archives ships scriba yet, so these are recipes to build rather than packages to install from a mirror:

| Distribution   | Package  | How to build it                                                                     |
|----------------+----------+-------------------------------------------------------------------------------------|
| Debian, Ubuntu | ~scriba~ | copy ~packaging/debian~ to the repository root, then ~dpkg-buildpackage -us -uc -b~ |
| openSUSE       | ~scriba~ | ~osc build~ with ~packaging/opensuse~                                               |
| Arch           | ~scriba~ | ~makepkg -si~ in ~packaging/arch~                                                   |

Each recipe carries its own dependency list, so a missing library fails the build with its name rather than producing a package that cannot load.

*** Which one?
:PROPERTIES:
:CUSTOM_ID: which-one
:END:
- *Guix* if you want the toolchain the project is tested with, and the ability to roll back a bad upgrade.
- *Nix* if the rest of your machine is already declarative; the flake pins nixpkgs and gives you a binary cache.
- *Container* if you only want to try the release, or reproduce a report on a machine that has nothing installed.
- *Distribution package* if you want the project managed by the same tool as the rest of your system, with its licence, manual page and launcher in the usual places.

** Installing
:PROPERTIES:
:CUSTOM_ID: installing
:END:

*** With Guix (recommended)
:PROPERTIES:
:CUSTOM_ID: with-guix-recommended
:END:

~guile-scriba~ is packaged in Guix proper:

#+begin_src shell
guix install guile-scriba
#+end_src

Or, better, declare it in your project's ~manifest.scm~ next to Guile:

#+begin_src scheme
(specifications->manifest
 (list "guile" "guile-json" "guile-scriba"))
#+end_src

and let ~guix shell~ provide it:

#+begin_src shell
guix shell -m manifest.scm -- guile my-program.scm
#+end_src

*** From this repository (latest code)
:PROPERTIES:
:CUSTOM_ID: from-this-repository-latest-code
:END:

Clone and use the pinned development environment, which includes Guile, Guile
JSON, Veritas and the documentation tooling:

#+begin_src shell
git clone https://codeberg.org/jjba23/scriba.git
cd scriba
guix shell -m manifest.scm -- guile -L ./src -c '(display "ready\n")'
#+end_src

~guix.scm~ packages the working tree itself (version ~dev~), which is handy for
building a local package or a ~guix shell -f guix.scm~:

#+begin_src shell
guix shell -f guix.scm -- guile -L ./src -c '(use-modules (scriba console))'
#+end_src

*** Manually, without Guix
:PROPERTIES:
:CUSTOM_ID: manually-without-guix
:END:

Scriba is plain Scheme source; nothing needs compiling. Clone the repository,
make sure [[https://github.com/aconchillo/guile-json][guile-json]] is available, and point Guile at the source tree:

#+begin_src shell
git clone https://codeberg.org/jjba23/scriba.git
export GUILE_LOAD_PATH="$PWD/scriba/src:$GUILE_LOAD_PATH"
guile -c '(use-modules (scriba console)) (display "scriba loaded\n")'
#+end_src

If you prefer a package definition of your own, adapt the one in ~guix.scm~:

#+begin_src scheme
(define-public guile-scriba
  (package
    (name "guile-scriba")
    (version "x.x.x")
    (source
     (origin
       (method git-fetch)
       (uri (git-reference
             (url "https://codeberg.org/jjba23/scriba.git")
             (commit (string-append "v" version))))
       (file-name (git-file-name name version))
       (sha256
        (base32 "<dependent on version>"))))
    (build-system guile-build-system)
    (arguments
     (list
      #:source-directory "src"))
    (propagated-inputs (list guile-json-4))
    (inputs (list guile-3.0))
    (synopsis "Structured logging framework for Guile Scheme")
    (description
     "Scriba is a structured logging library for GNU Guile that prioritizes
flexibility and observability.")
    (home-page "https://codeberg.org/jjba23/scriba")
    (license license:expat)))
#+end_src

** Requirements
:PROPERTIES:
:CUSTOM_ID: requirements
:END:

| Requirement  | Version      | Notes                                                  |
|--------------+--------------+--------------------------------------------------------|
| GNU Guile    | 3.0 or newer | Tested with ~guile-3.0~ and ~guile-next~               |
| guile-json   | 4.x          | Required only by the JSON backend and the auto-logger  |
| POSIX system | —            | Uses ~gethostname~, ~stat~, ~localtime~, file rotation |

Development and testing additionally use [[https://codeberg.org/jjba23/veritas][Veritas]] (the test framework),
[[https://codeberg.org/jjba23/maak][maak]] (task runner) and [[https://codeberg.org/luis-felipe/guile-documenta][Documenta]] (API docs) — all provided by
~manifest.scm~.
